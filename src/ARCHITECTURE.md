# Архитектура

## Три слоя и одно правило

```
presentation (curses) ──► domain ◄── datalayer (json)
                            ▲
                       main.py собирает всё вместе
```

**Зависимости идут только к `domain`.** Домен не импортирует `curses`, `json`, `presentation`
и `datalayer`. Это проверяет `tests/test_architecture.py`: нарушите правило, и тесты упадут.

| Слой | Что внутри | Что нельзя |
|---|---|---|
| `domain/` | сущности, бой, генерация уровней, ИИ врагов, `GameSession` | curses, json, тексты для игрока, глобальный `random` |
| `presentation/` | клавиши, отрисовка, меню, тексты сообщений | менять состояние игры в обход `session.handle()` |
| `datalayer/` | сохранение и загрузка (Задание 5) | знать про curses и presentation |
| `main.py` | создаёт `GameSession`, запускает curses | логику |

## Как устроен один ход

```
клавиша ──► input.translate() ──► Command ──► session.handle(Command) ──► [Event, ...]
                                                  │                          │
                                         меняет состояние мира        messages.format_event()
                                                                      stats.record()
```

- **Команда** (`domain/commands.py`) - что игрок хочет: `Move`, `UseItem`.
- **Событие** (`domain/events.py`) - что произошло: `PlayerAttacked`, `ItemPickedUp`, `LevelChanged`...
- Домен никогда не формирует текст. Строки «Вы промахнулись» живут в `presentation/messages.py`.
- Статистика (`RunStats`) собирается из событий, поэтому счётчики не разбросаны по коду.

Порядок внутри `handle()`: действие игрока -> эффекты эликсиров -> ход каждого врага -> проверка смерти.
Упор в стену ход не тратит. Переход на следующий уровень тоже: враги нового уровня сразу не ходят.

## Ключевые решения

1. **Случайность приходит снаружи.** Везде `rng: random.Random`. В тестах подставляется
   «всегда попал»/«всегда промах», игра с `--seed N` воспроизводима.
2. **Уровень - это объекты, а не текст.** `Level` хранит сетку тайлов, `Room`, `Corridor`
   (с проёмами и всеми клетками), врагов и предметы. Из этого получится туман войны
   и сохранение «вплоть до расположения сущностей».
3. **Данные отдельно от логики.** Типы врагов (`enemies/types.py`), предметы (`catalog.py`)
   и все числа (`balance.py`) - таблицы. Баланс меняется без правки алгоритмов.
4. **Генератор сам проверяет себя.** `generate_level` повторяет попытку, пока
   `validate.find_problems()` не вернёт пустой список (связность, выход, чистая стартовая комната...).
5. **Порты вместо прямых зависимостей.** `domain/ports.py` описывает `SaveRepository`;
   реализация будет в `datalayer/`, домен о ней не знает.

## Куда добавлять новое

| Хочу добавить | Что делать |
|---|---|
| Тип врага | запись в `EnemyKind` и `SPECS` (`enemies/types.py`), паттерн в `enemies/behaviors.py::PATTERNS`, символ и цвет в `presentation/theme.py`. Особенность боя - новый `Trait` и ветка в `combat.py` |
| Предмет | шаблон в `catalog.py` (`ITEM_TEMPLATES`); новый *тип* предмета - ещё `ItemType`, ветка в `GameSession._use_item`, подпись в `messages.item_label` |
| Команду игрока | dataclass в `commands.py`, ветка `match` в `GameSession.handle`, клавиша в `presentation/input.py` |
| Событие | dataclass в `events.py`, текст в `messages.format_event`, при необходимости учёт в `RunStats.record` |
| Число баланса | `domain/balance.py` |

## Что готово и что дальше

| Задание | Статус |
|---|---|
| 1. Сущности | готово |
| 2. Геймплей | готово частично: зомби и вампир (первый удар мимо, вытягивание макс. здоровья). **Нет:** привидение, огр, змей-маг |
| 3. Генерация | готово: сетка 3×3, коридоры с геометрией, проверка связности |
| 4. Отрисовка | карта, акторы, статус, меню предметов, WASD и `h/j/k/e`. **Нет:** туман войны (нужен ray casting, заготовка `geometry.bresenham` есть), отдельный экран статистики/рекордов |
| 5. Datalayer | порт описан, реализации нет |
| 6-9. Бонусы | не начаты |

Рекомендуемый порядок: оставшиеся 3 врага -> туман войны -> datalayer -> таблица рекордов -> бонусы.

## Что изменилось по сравнению с первым прототипом

| Было | Стало |
|---|---|
| `domain/logic.py` (`Entity`, `Player`, `Enemy`, `Game`) | `domain/models/entities.py`, `domain/session.py`; подклассы `Zombie/Vampire` заменены данными в `SPECS` |
| `attack()`, `hit_chance()` | `domain/combat.py` (та же формула, добавлены особенности вампира) |
| `generator.py` (BSP, текстовые файлы `mapN.txt`) | `domain/generation/` (сетка 3×3, объекты `Room`/`Corridor`) |
| `map.py`, `levels/*.txt` | не нужны: уровень живёт в памяти как `Level` |
| `Game.log` со строками | события + `presentation/messages.py` |
| `Game.pending_item` (y/n) | подбор автоматический, как в задании |
| `view.py` | `presentation/renderer.py`, `input.py`, `menus.py`, `app.py` |
| стрелки | WASD (стрелки остались как запасной вариант) |
| сокровища - предметы в списке | число в `Backpack.treasure` |

Числа, которые изменены осознанно (всё в `balance.py`): врагов на уровень растёт на 1, а не на 2
(на 21 уровне было бы 43 врага); у вампира `move_every = 1` вместо 4 (с 4 он был медленнее зомби,
что противоречит «высокая ловкость»); карта 78×21 вместо 60×22, чтобы влезать в терминал 80×24.
