c# Как устроена наша игра

Это описание текущего кода, без истории переделок. Оно рассчитано на чтение
перед разбором проекта и защитой. История изменений остаётся в `ARCHITECTURE.md`.

## 1. Общая идея

Игра — пошаговый roguelike в терминале. Игрок исследует подземелье, собирает
предметы, сражается и ищет выход. Всего 21 уровень, на каждом — 9 комнат.
В проекте есть цветные двери с ключами и мимик. Автоматическая подстройка
сложности и 3D не реализованы. Сложность растёт по номеру уровня.

Код разделён на три слоя:

| Папка | За что отвечает | Пример |
|---|---|---|
| `domain` | Правила игры и её состояние | Можно ли открыть дверь, куда пойдёт враг |
| `presentation` | Клавиатура и изображение в терминале | Прочитать D, нарисовать карту, показать сообщение |
| `datalayer` | Сохранения и рекорды | Записать состояние игры в JSON |

`main.py` соединяет эти части: создаёт хранилище, задаёт создание новой сессии
и запускает интерфейс через `curses.wrapper`. Эта функция также возвращает
терминал в обычный режим после завершения приложения.

Направление зависимостей простое:

```text
main.py
  ├── presentation → domain
  └── datalayer    → domain
```

`domain` не импортирует интерфейс или файловое хранилище. Поэтому правила
игры можно проверять без окна терминала и без файлов сохранения.

## 2. Где искать нужный код

### Правила игры: domain

| Файл | Содержимое |
|---|---|
| `session.py` | Игровая сессия: команды игрока, ход мира, переходы и завершение игры |
| `level.py` | Координаты, клетки, комнаты, коридоры, уровень, цвета ключей и память карты |
| `entities.py` | Игрок, враги, их характеристики, временные эффекты и создание врагов |
| `items.py` | Предметы, рюкзак, шаблоны и случайные параметры предметов |
| `combat.py` | Попадание, урон, особенности атак и награда за врага |
| `enemies.py` | Перемещение врагов вне преследования и невидимость привидения |
| `generation.py` | Создание комнат, коридоров и наполнения уровня |
| `validation.py` | Расстановка дверей и ключей, проверка связности и доступности |
| `geometry.py` | Поиск в ширину и линия Брезенхэма |
| `visibility.py` | Определение клеток, видимых игроку сейчас |
| `commands.py` | Команды: движение и использование предмета |
| `events.py` | Факты о произошедшем: подобран ключ, нанесён удар и другие |
| `stats.py` | Статистика прохождения и её обновление по событиям |
| `balance.py` | Размеры мира, параметры игрока, боя и роста сложности |
| `ports.py` | Описание операций, которые должно предоставлять хранилище |

Базовые характеристики видов врагов находятся в `entities.py`, параметры
предметов — в `items.py`. Не все числа собраны в `balance.py`.

### Интерфейс: presentation

| Файл | Содержимое |
|---|---|
| `app.py` | Главное меню, игровой цикл, вызовы сохранения и завершение сессии |
| `input.py` | Преобразование клавиш в команды или запрос открытия меню |
| `menus.py` | Главное меню и выбор предмета в рюкзаке |
| `renderer.py` | Отрисовка карты, существ, предметов и панели состояния |
| `theme.py` | Символы, цвета и правила отображения запомненных клеток |
| `messages.py` | Преобразование событий в сообщения для игрока |
| `screens.py` | Таблица рекордов и экран результата |

### Работа с файлами: datalayer

| Файл | Содержимое |
|---|---|
| `serializers.py` | Преобразование объектов игры в словари и списки и обратно |
| `json_repository.py` | Чтение и запись JSON-файлов сохранения и рекордов |

Пустые `__init__.py` обозначают пакеты Python. Удалять их ради уменьшения
числа файлов не требуется.

## 3. Где хранится состояние

Главный объект — `GameSession`. В нём находятся:

- `player` — игрок, его здоровье, оружие, рюкзак, ключи и эффекты;
- `level` — текущая карта с врагами, предметами, дверями и ключами на полу;
- `stats` — статистика всей попытки;
- `exploration.seen` — клетки, которые игрок уже видел на текущем уровне;
- `visible` — клетки, которые он видит сейчас;
- `state` — игра продолжается, выиграна или проиграна;
- `rng` — генератор случайных чисел.

`Pos(x, y)` — координата клетки: X направлен вправо, Y — вниз.
Карта хранится как строки клеток: `tiles[y][x]`.

Важно различать основу карты и объекты поверх неё. `Tile.DOORWAY` — проём
в стене, а запись в `level.doors` — закрытая дверь в этом проёме.
После открытия запись удаляется, проём остаётся. Предметы и ключи тоже
хранятся отдельно от клеток карты, в словарях с координатами в качестве ключей.

## 4. Что происходит после нажатия клавиши

Например, игрок нажал D:

1. `input.py` превращает клавишу в `Move(1, 0)`.
2. `app.py` передаёт команду в `session.handle()`.
3. Сессия определяет клетку справа и выполняет действие: движение, атаку
   или попытку открыть дверь.
4. Если действие потратило ход и игра продолжается, сессия обрабатывает
   временные эффекты и действия врагов.
5. Сессия обновляет статистику по событиям и пересчитывает видимость.
6. `app.py` получает события, переводит их в сообщения и при необходимости
   сохраняет игру. На следующей итерации рисуется новое состояние.

Команда — просьба что-то сделать. Событие — сообщение о том, что уже произошло.
Например, `Move` может привести к `Moved`, `PlayerAttacked` или `DoorLocked`.
Это обычные объекты данных, отдельного диспетчера событий в проекте нет.

Шаг в стену и попытка открыть дверь без ключа не тратят ход. Атака тратит ход,
даже при промахе. Меню само по себе мир не двигает. Если игрок усыплён,
следующая игровая команда расходуется на пропуск хода. При переходе на новый
уровень его враги сразу не действуют.

## 5. Как создаётся уровень

`generate_level()` выполняет следующие действия:

1. Делит карту 78×21 на сетку 3×3 и создаёт по комнате в каждой секции.
2. Выбирает связи между соседними секциями обходом со стеком. Каждая новая
   комната присоединяется к уже достигнутым: получается связное дерево
   из 9 комнат и 8 связей. Затем добавляется от 0 до 2 лишних связей.
3. Строит коридоры с поворотами и наносит комнаты и коридоры на карту.
4. Выбирает стартовую комнату и клетку старта. Поиск в ширину вычисляет
   расстояния; выход размещается в центре самой далёкой по этому расчёту комнаты.
5. Размещает врагов и полезные предметы вне стартовой комнаты и не на выходе.
6. Добавляет двери и ключи, затем проверяет результат.

Неподходящая раскладка отбрасывается. Есть предел в 50 попыток, после которого
возникает ошибка, а не бесконечный цикл генерации.

Комнаты и коридоры хранятся как отдельные объекты, поскольку нужны для проверок,
видимости и поведения врагов. Сетка клеток нужна для движения и отрисовки.
Это два представления одного уровня для разных задач.

## 6. Как двери не создают тупик

Есть три цвета: красный, жёлтый и синий. Подобранный ключ остаётся у игрока
до перехода на следующий уровень и не расходуется при открытии.
Закрытая дверь мешает движению врагов и обзору из коридора.

На первом уровне дверей нет. На уровнях 2, 5 и 8 желаемое количество
увеличивается до одной, двух и трёх. Фактическое количество может быть меньше.

Сначала выбираются коридоры, удаление которых разрывает связи между комнатами.
Такая связь называется мостом. Если есть подходящий мост на пути к выходу,
первая дверь выбирается там. Затем ключи кладутся по одному только в уже
достижимую область, вне стартовой комнаты, врагов и предметов.

Проверка `collect_keys()` — поиск в ширину с учётом ключей:

1. Начинаем без ключей и ищем все достижимые клетки. Закрытые двери непроходимы.
2. Находим ключи в достигнутых клетках.
3. Повторяем поиск с найденными цветами: соответствующие двери теперь
   считаются проходимыми.
4. Заканчиваем, когда новых цветов больше нет.

Например, сначала доступен красный ключ. Он разрешает пройти красную дверь,
за которой находится синий ключ. Следующий обход разрешает и синюю дверь.
Если красный ключ лежит за собственной дверью и обходного пути нет,
проверка обнаружит недоступность.

Это проверка возможностей игрока: она не двигает настоящего персонажа
и не удаляет настоящие двери. В конце проверяются доступность выхода
и каждого ключа, наличие нужных цветов и правильное размещение объектов.
Если расстановка не удалась, генератор пробует меньше дверей, вплоть до нуля.
Проверка защищает от тупиков из-за замков; она не гарантирует победу в боях.

## 7. Как устроены бой и враги

При движении в клетку врага игрок атакует, оставаясь на своей клетке.
`combat.py` определяет попадание по разнице ловкости, вычисляет урон
и уменьшает здоровье цели. Обычный урон игрока — сила плюс сила оружия.
Вероятность попадания ограничена снизу и сверху. За убитого врага сокровища
сразу прибавляются в рюкзак, отдельный предмет на полу не появляется.

У врага есть тип (`EnemyKind`), исходные параметры (`EnemySpec`) и изменяемое
состояние: позиция, здоровье, таймер действия и признаки особых способностей.
Создание врага находится в `entities.py`, движение вне преследования —
в `enemies.py`, последовательность действий — в `session.py`.

При преследовании все виды используют один поиск кратчайшего пути по четырём
соседним клеткам и делают один шаг. Путь ограничен враждебностью; если подходящего
пути нет, выбирается обычное движение своего вида. Враги действуют с интервалом,
указанным в `move_every`, а не обязательно после каждой команды игрока.

Особенности видов:

- зомби перемещается обычным случайным образом;
- вампир избегает первого удара по себе и при успешной атаке снижает максимум здоровья;
- привидение телепортируется по комнате и меняет видимость до начала боя;
  первая попытка атаки любой стороны делает его постоянно видимым;
- огр вне преследования может пройти две клетки, после атаки пропускает один
  ход, а следующая его атака гарантированно попадает;
- змей-маг вне преследования предпочитает менять направление диагонального
  движения, а при попадании может усыпить игрока;
- мимик притворяется предметом, затем раскрывается при сближении или атаке игрока.

Имя `WIZZARD` в коде обозначает змея-мага. Старое написание оставлено
для совместимости с сохранениями.

## 8. Предметы и эффекты

В рюкзаке до 9 предметов каждого типа. Сокровища хранятся отдельным числом.
Наступив на предмет, игрок автоматически подбирает его, если есть место.

Еда восстанавливает здоровье. Свиток меняет характеристику постоянно.
Эликсир добавляет временный бонус, который хранится в `ActiveEffect` вместе
с оставшимся количеством ходов. Когда срок истекает, бонус снимается.
При уменьшении максимума здоровья после эффекта игроку остаётся хотя бы
одна единица здоровья.

Используемые еда, свитки и эликсиры исчезают. При замене оружия прежнее
кладётся на свободную соседнюю клетку. Если такой клетки нет, замена отменяется.
Выбор 0 убирает оружие в рюкзак, если там есть место.

Здоровье и сила считаются целыми числами. `SCALE = 10` означает, что один
блок полоски здоровья соответствует десяти единицам. Это масштаб отображения,
а не отдельная характеристика персонажа.

## 9. Видимость и отрисовка

Внутри комнаты видны её пол и окружающие стены с проёмами. В коридоре и проёме
используются лучи к клеткам в пределах радиуса 8. Алгоритм Брезенхэма перечисляет
клетки луча. Стена или закрытая дверь видна сама, но останавливает луч.
Также нельзя смотреть по диагонали сквозь две соприкасающиеся преграды.

`visible` пересчитывается после команды. `exploration.seen` накапливает
увиденное до конца уровня. Рендерер использует оба множества: сейчас видимые
объекты показываются полностью, а из памяти остаются стены, проёмы и коридоры.
Ключи и предметы из памяти не показываются. Закрытые двери запоминаются.

Рендерер читает состояние игры. Он не вычисляет попадания, не двигает врагов
и не решает, доступен ли ключ.

## 10. Сохранения и рекорды

`SaveRepository` — короткое описание нужных операций: сохранить, загрузить,
удалить сессию, добавить результат и получить лучшие результаты.
`JsonRepository` предоставляет эти операции. Явного наследования не требуется:
`Protocol` описывает ожидаемые методы для проверки типов.

Сохранение проходит двумя шагами: `serializers.py` переводит объекты в обычные
словари и списки, а `json_repository.py` записывает их через `json`.
При загрузке выполняются обратные преобразования.

Рядом с `main.py` автоматически создаётся папка `saves`:

- `save.json` — одна продолжаемая сессия;
- `records.json` — результаты завершённых попыток.

Сохраняются текущая карта, существа и их состояния, предметы, двери, ключи,
игрок, эффекты, статистика и память исследования. Видимость вычисляется заново.
Запись происходит после перехода между уровнями и при выходе из игры в меню.
При победе или смерти добавляется рекорд, а продолжаемое сохранение удаляется.
Рекорды сортируются по сокровищам, при равенстве — по достигнутому уровню.

Состояние генератора случайных чисел не сохраняется. Текущий уровень
восстанавливается, но будущие случайные события после загрузки могут отличаться.
Наличие загрузки старых полей с начальными значениями не означает совместимость
с любым произвольным или повреждённым JSON.

## 11. Как запустить и проверить

Нужен Python 3.10 и терминал минимум 81 столбец на 30 строк.
Из папки `src`:

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python main.py
```

Для одной игры без инструментов разработки достаточно `requirements.txt`.
На Windows он устанавливает `windows-curses`, на macOS и Linux используется
модуль curses из Python. Можно указать `python main.py --seed 42` для
повторяемого создания мира при одинаковом коде и последовательности действий.

Управление: WASD или стрелки — движение; H — оружие; J — еда;
K — эликсир; E — свиток; Q — выход в меню с сохранением.
Предмет выбирается цифрой 1–9, для оружия доступен также 0.

Проверки:

```bash
python -m pytest -q
python -m ruff check .
```

Тесты в `tests` проверяют правила игры, генерацию, ключи, сохранения,
интерфейс и прохождение уровней ботом. `pytest.ini` задаёт папку тестов,
`pyproject.toml` — настройки проверки кода. `Makefile` сокращает команды
запуска и проверок. `.venv` — локальное окружение, а кэши Python и тестов —
временные файлы. Их не нужно включать в сдаваемую копию или Git.

Автоматические тесты не заменяют ручную оценку цветов, символов в конкретном
терминале и сложности игры. Этот документ описывает реализацию, а не заявляет,
что проведён окончательный аудит каждого требования задания.

## 12. В каком порядке разбирать проект

Начните с `main.py` и `presentation/app.py`, чтобы увидеть запуск и цикл.
Затем прочитайте `GameSession.handle()` и `_move_player()` в `domain/session.py`.
После этого разберите структуры в `level.py`, `entities.py` и `items.py`.
Остальные части удобно изучать по одному сценарию: атака, генерация,
открытие двери, видимость, сохранение.

Для защиты полезно уметь проследить один конкретный пример от клавиши до
результата и объяснить: где изменилось состояние, почему потратился ход,
какие события появились и что попало в сохранение. Так легче понять проект,
чем запоминать перечень файлов.
